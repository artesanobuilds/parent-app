## What shipped

The Chief of Staff grew from camps-only to **five verticals behind one agent** — the GTM
mandate "one agent with five entry doors, not five features on a homepage":

- **Registry, not agents.** `app/cos/verticals.py` — a data-only `VerticalProfile` registry
  (labels, date model, capability booleans, to-do wording, door copy). One static sectioned
  system prompt; conditionals stay code; verticals are card attributes + chip filters, never
  navigation. Flags gate DOOR VISIBILITY only, at `GET /cos/verticals`, fail-open.
- **Date model (v17):** `start_date`/`end_date`/RFC-5545 `rrule` with
  `storage.set_activity_dates` as the single write path; derived
  `recurring_appointments`/calendar rows regenerate, never hand-edit. Server-rendered `when`
  strings ("Tuesdays 4:00 PM through Dec 15", "Jun 14 – Jun 18") rendered verbatim by both
  clients.
- **Registration-window watchlist (v18)** — the GTM Pillar-1 retention engine, built as a
  notification-SLO product: append-only `window_notifications` delivery log (idempotency +
  re-arm-on-date-change + audit), tz-aware notify-before-never-after due rules, catch-up
  sweep worker, durable-first delivery → blocking APNs push → recorded outcome,
  estimated-vs-confirmed trust design, miss-detector gauge.
- **School-life ingest:** many-objects extraction (one newsletter → N items),
  `event_kind` → typed to-do chains, verbatim source-snippet provenance on every extracted
  deadline, cap-and-park, exploring/pending-only blast radius, correction-flywheel events.
- **Trips (thin):** date_range, coverage, packing/consent/meds prep to-dos on booking,
  explicit no-bookings scope.
- **Five-doors UI** on iOS + web: chip filters, "Plan something" door disclosure, chat door
  starters, doors last-good caches. Zero client changes needed for the final vertical —
  the registry-shaped proof.
- **Telemetry in the same PRs:** `observability.count()/observe()` facades, `cos_*` +
  `watchlist_*` metrics, PostHog funnel events, dashboards-as-code
  (`setup/grafana/vertical-expansion-dashboard.json`, 17 panels incl. the Watchlist-SLO
  row), 4 Grafana alert rules (live + MCP-verified 2026-07-12).
- **Public docs** at `/dashboard/docs` (outside the auth guard): 13 pages incl. coach +
  kids' companions, illustrated with real product screenshots captured against an isolated
  demo backend with a synthetic family, plus hand-authored Hearth SVG diagrams.

## The deploy incident (~30 min prod outage)

Migration v16 ran its backfill `UPDATE` and `CREATE INDEX` in one transaction; DuckDB
refuses (`Cannot create index with outstanding updates`) — but only on a DB **with rows**,
so every empty test/dev DB passed and prod crash-looped at boot. The transactional wrapper
rolled back cleanly (no data touched). Hotfix `5ddf496` moved the index to its own migration
(v19) and added a regression test that runs the migration chain against a **populated**
pre-v16 schema. Two more pre-deploy catches: watchlist parquets missing from `.dockerignore`
(now structurally guarded by `tests/test_dockerignore_guard.py`) and the dashboard JSON
missing its promised Watchlist-SLO row.
