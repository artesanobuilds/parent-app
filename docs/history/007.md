# 007: Onboarding choice UX, memory persistence, and profile-aware agents

**Date:** December 29, 2025  
**Objective:** Add an agent selection UX, persist in-memory chat/onboarding/profile data locally, and enrich agents with profile context and typed tool schemas for more reliable data collection.

## Decisions
- Present users with a post-username agent choice (Onboarding vs Coaching) using branded icon badges and allow switching anytime.
- Introduce storage abstractions (Strategy + Repository patterns) so memory and profile persistence can swap backends (local files now, DB later) without touching business logic.
- Persist per-user chat threads, onboarding threads, and profiles to `local-storage/<user>/` on shutdown; load them on startup if present.
- Surface stored profiles into both coaching and onboarding prompts (onboarding now too), pruning empties and instructing the agent to keep enriching profiles without echoing raw JSON.
- Tighten tool schemas with Pydantic models for parent/child updates (partial updates allowed), and document all accepted fields in tool docstrings for better model guidance.

## Implementation
- iOS app (SwiftUI):
  - Added agent selection sheet after username capture; “Change Agent” button on the toolbar; separate titles/descriptions per mode.
  - Restyled toolbar actions as coral-outlined circular badges for Reset, Server, and Agents; reduced size to save space.
  - Reused chat UI for onboarding by switching endpoint via mode.
- Backend persistence and abstractions:
  - Added `StorageBackend` interface + `LocalFileStorage` (Strategy) writing JSON under `local-storage/<user>/`.
  - Added `MemoryRepository` (Repository) wrapping chat/onboarding thread maps with snapshot/load APIs.
  - Profiling service gained export/import snapshot methods.
  - FastAPI lifespan now loads persisted chat/onboarding/profile snapshots on startup and saves them on shutdown; `/memory/{user_id}` now returns chat, onboarding, and profile snapshots.
- Agents:
  - Coaching agent already used profile context; onboarding agent now also injects pruned profile JSON into its system prompt with guidance to keep enriching.
  - Onboarding tools `FoundMoreAboutParent` / `FoundMoreAboutChild` now accept Pydantic models (`ParentUpdate`, `ChildUpdate`) with all fields optional (child_name required) and log structured payloads.
  - Fixed missing `json` import and ensured profile-context caching invalidates the agent when profiles change.

- Manual: iOS simulator checks for agent badges, agent switching, and onboarding/coaching headers. No automated tests run.
