# 008: Onboarding demographic enrichment + Railway recovery

**Date:** May 7, 2026
**Objective:** Restore the production backend after a langgraph dependency break, get OpenAI calls flowing again, then add a coherent set of demographic fields end-to-end so the coaching agent can personalize on locale, language, life stage, employment, and per-child grade/pronouns.

## Decisions
- **Pin transitive dep** rather than bump majors: `langgraph==1.0.5` allowed `langgraph-prebuilt<1.1`, but `prebuilt` 1.0.10 imports `ExecutionInfo` only present in `langgraph>=1.1`. Pinning `langgraph-prebuilt==1.0.8` (last version without that import) was the lowest-risk fix vs. a langgraph 1.1.x bump that would cascade to langchain-core ≥1.3.
- **Schemaless storage stays.** DuckDB stores profiles as a JSON blob in `user_data`. New profile fields just appear on next save — no migration script, no per-field column. Defer normalization until query/analytics needs justify it.
- **Two onboarding paths must stay in sync.** The structured form (`OnboardingView` → `/profile/seed`) and the conversational `/onboarding-chat` agent capture the same shape; every field added to the form is also added to the agent's `ParentUpdate` Pydantic + system prompt, and to the silent-extraction `ParentUpdate` in the coaching agent.
- **Demographics come right after Name** (new Step 2 "About you"), before Kids. Demographics-first framing keeps later steps light and lets the agent calibrate from the start.
- **All new demographic fields optional** with a "Skip" affordance on the new step. Parent age stored as bracket only (`<25`, `25-34`, …, `prefer_not_to_say`) — never an exact birth year. "Prefer not to say" is a first-class option.
- **Reconcile, don't duplicate.** A pre-planning sweep found that `cultural_background`, `employment`, parent `pronouns`, child `pronouns`, and child `grade_band` already existed in `ParentProfile`/`ChildProfile` — they just weren't surfaced in the form. Truly new model fields ended up being only the 5 location/life-stage parent fields.

### Demographic profile enrichment

**Backend (`mvp-backend/app/`):**
- `profiling.py` — added 5 new fields to `ParentProfile`: `postal_code`, `country`, `primary_language`, `parent_age_range`, `adults_in_household`. `apply_update` already merges generically — no logic changes.
- `onboarding_agent.py` — mirrored the 5 fields in `ParentUpdate` Pydantic; rewrote the system prompt's "What to gather" list to call out demographics + the previously unsurfaced fields (cultural_background, employment, pronouns, child grade_band); updated the `FoundMoreAboutParent` tool docstring.
- `agent.py` — mirrored the 5 fields in the coaching agent's silent-extraction `ParentUpdate` so demographics dropped mid-chat get captured.
- `server.py` — extended `OnboardingSeedRequest` with 8 new parent keys (`postal_code`, `country`, `primary_language`, `parent_age_range`, `adults_in_household`, `cultural_background`, `employment`, `pronouns`) and 2 per-kid keys (`pronouns`, `grade_band`); handler passes them through to `update_parent_profile` / `update_child_profile`.

**Frontend (`mvp/MVP/`):**
- `OnboardingView.swift` —
  - Extended `OnboardingData` and `KidEntry` structs with the new fields.
  - Bumped `totalSteps` 8 → 9 and renumbered every screen's `advance(to:)` and `onboardingHeader(backTo:, step:)` calls.
  - Added a new **Step 2 "About you"** with: zip + country menu, primary-language picker, parent age range segmented control, adults-in-household stepper (1–4), employment picker, parent pronouns chips, free-text cultural background. Skip button in the header.
  - Added pronouns chips + grade-band menu inside the existing kid card.
  - Updated the preview screen's `onComplete` payload to send all new values.
- `SwayApp.swift` — `seedProfileOnBackend` now serializes the 8 new parent keys + 2 per-kid keys into the `/profile/seed` JSON body.
