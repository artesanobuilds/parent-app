# Release Notes — 2026-05-07

Manual QA guide for everything that landed in this session. Walk it top to bottom; each section is independent and can be skipped if you're tight on time.

**Prerequisites**
- Local server running on `:8904` from `mvp-backend/`. Start with:
  ```
  cd mvp-backend && uvicorn app.server:app --reload --host 0.0.0.0 --port 8904
  ```
- iOS app built from this branch in Xcode against `localhost:8904`.
- One Bearer token issued and exported, used for the backend curl tests:
  ```
  export TOKEN=$(curl -sS -X POST http://localhost:8904/auth/issue-token \
    -H 'Content-Type: application/json' \
    -d '{"user_id":"qa-rn"}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')
  echo "TOKEN=${TOKEN:0:8}..."
  ```

## 1. Onboarding — new "About you" demographic step *(iOS only)*

**What changed.** Onboarding step count is now 9 (was 8). A new step **2: "About you"** sits between Name and Kids and collects: zip, country, primary language, parent age range, adults-in-household, employment, parent pronouns, cultural background. Kid cards now also collect pronouns + grade band. The preview screen renders a "Here's what we have" card with a personalized summary.

**Test path.**
1. In Xcode, run a fresh install on the simulator (`Settings → erase` or delete the app first).
2. Tap **I'm new here**.
3. Enter a name → tap Next.
4. **About you step (new):**
   - Verify the **Skip** button on the top right.
   - Type a zip → confirm the country flag prefixes the chip preview later.
   - Try the country menu — picker shows US/MX/CA/GB/Other.
   - Pick a language.
   - Pick an age range — confirm "Prefer not to say" is present.
   - Use the adults-in-household stepper — clamps at 1 and 4.
   - Pick employment, pronouns, cultural background.
   - Tap Next.
5. **Kids step:** add a kid name → confirm the temperament chips, the new pronouns chips, and the Grade menu all appear.
6. Walk the rest of the steps.
7. **Preview step:** verify the "Here's what we have" card renders the exact values you typed (e.g. `📍 90210 · English · 35–44 · Full-time · she/her · Mexican-American · Co-parenting · 2 adults`). Per-kid line: `🌿 Ari (7) · sensitive · she/her · 2 grade`.
8. Tap **Let's go**.
9. **Backend round-trip:** in the terminal where uvicorn runs, you should see a POST to `/profile/seed`. Confirm the body shape with:
   ```
   curl -sS http://localhost:8904/memory/<your-parent-name> | python3 -m json.tool
   ```
   The `parent` block should include `postal_code`, `country`, `primary_language`, `parent_age_range`, `adults_in_household`, `employment`, `cultural_background`, `pronouns`. Each child row should include `pronouns` and `grade_band`.

**Expected failure.** None — every new field is optional. Skipping the About-you step entirely should still work; the seed POST drops the keys silently.

**Edge case:** the welcome screen's "Welcome back" path bypasses every demographic step. That's intentional; returning users get a stub profile in the seed payload.

## 2. Crisis-regex coverage *(backend)*

**What changed.** The crisis pattern set went from 7 to 40, tagged across 8 categories with severity (`imminent`/`high`/`passive`):
- suicide_direct (intent / method / timeframe)
- suicide_passive (ideation without intent)
- self_harm
- abuse (parent/uncle/teacher hits/touches)
- grooming (send pics, our secret, meet up)
- ed (eating disorder)
- substance (overdose hints)
- Spanish equivalents (suicide_direct, self_harm, abuse, grooming)

**Test path.**

## 3. Streaming-moderator buffer-bypass fix *(backend)*

**What changed.** Before: once the model's output cleared the 120-char gate, every subsequent token streamed to the kid unmoderated until end-of-stream. Now: the moderator keeps a sliding window, re-runs the cheap crisis regex on every token append, and re-runs the heavy moderation every ~240 chars.

**Test path.**
```
cd mvp-backend && /Users/miguelalvarado/Coding/parent-app/.venv/bin/python -c "
from dotenv import load_dotenv; load_dotenv()
from app.moderation import StreamingModerator
sm = StreamingModerator(user_id='qa', kid_name='Ari', agent_id='qa-agent', age_band='middle')
prefix = 'This is a long innocuous chatty intro about dinosaurs and rainbows that easily exceeds the 120 character gate. ' * 2
crisis_tail = ' But honestly I want to die.'
chunks = []
for tok in [prefix, crisis_tail]:
    chunks += sm.feed(tok)
print('state:', sm.state.name)
print('block category/severity:', sm.block_reason.category, '/', sm.block_reason.severity)
"
```

**Expected.** `state: BLOCKED`, `block category/severity: crisis / crisis`. The bug was that the post-gate "I want to die" used to slip through; now it doesn't.

## 4. Hashed auth tokens with 30-day TTL *(backend)*

**What changed.** Tokens are sha256-hashed at rest. Lookup recomputes the hash on the inbound `Authorization: Bearer ...`. Every new token has `expires_at = created_at + 30d` and `last_used_at`. Legacy plaintext rows from before today fail closed (no `expires_at`).

**Test path.**
```
# 1. Issue a token, save it
TOKEN=$(curl -sS -X POST http://localhost:8904/auth/issue-token \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"qa-token"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["token"])')
echo "Raw token: ${TOKEN:0:8}..."

# 2. Use it -> 200
curl -sS -o /dev/null -w "with raw token: %{http_code}\n" \
  http://localhost:8904/memory/qa-token -H "Authorization: Bearer $TOKEN"

# 3. Use a wrong token -> 401
curl -sS -o /dev/null -w "with bogus token: %{http_code}\n" \
  http://localhost:8904/memory/qa-token -H "Authorization: Bearer wrong-token-here"

# 4. Try to bypass auth (no header) -> 401
curl -sS -o /dev/null -w "no auth header: %{http_code}\n" \
  http://localhost:8904/memory/qa-token
```

**Expected.** `200`, `401`, `401`. To prove the storage is hashed (not the raw), kill the local uvicorn briefly and run:
```
duckdb mvp-backend/data/mvp.duckdb \
  "SELECT length(token) FROM auth_tokens WHERE user_id = 'qa-token' ORDER BY created_at DESC LIMIT 1;"
```
Length should be **64** (sha256 hex), not 32 (raw uuid hex).

## 5. `/auth/issue-token` rate limit *(backend)*

**What changed.** Token issuance is now capped at **5 per hour per source IP** to slow down token-flooding amplifier attacks. Tunable via `RATE_LIMIT_AUTH_PER_HOUR`.

**Test path.**

**Reset:** restart uvicorn (in-process bucket; this is documented; see roadmap "Family Companion v0 — pre-beta blockers / Observability").

## 6. Crisis lock + revive *(backend, gated by /kid-chat path)*

**What changed.** When a kid input or model output trips a crisis pattern, the agent is now:
1. **Persistently locked** in DuckDB (`kid_agent_crisis_locks`), survives Railway restart.
2. **Disabled** at the config level (`kid_agent_configs.enabled = FALSE`).
3. **Killed in-process** (`moderation.kill_agent`) for the current request.

Subsequent `/kid-chat` calls return a static "your grown-up needs to check in with you first" message until a parent calls `POST /kid-agent/{agent_id}/revive`. Parents can list their locked agents via `GET /kid-agent/crisis-locks?user_id=...`.

**Test path (without an iOS client, this is awkward — easier with iOS).**

If you have a kid agent set up via the iOS app:
```
# 1. Trigger a crisis input via /kid-chat (replace USER_ID, KID_NAME, TOKEN)
curl -sS -N -X POST http://localhost:8904/kid-chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"user_id":"<USER_ID>","kid_name":"<KID_NAME>","thread_id":"qa-crisis","message":"I want to die"}' | head -c 800

# 2. List locks (should show your kid's agent)
curl -sS "http://localhost:8904/kid-agent/crisis-locks?user_id=<USER_ID>" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# 3. Try to chat again — should return the freeze message immediately
curl -sS -N -X POST http://localhost:8904/kid-chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"user_id":"<USER_ID>","kid_name":"<KID_NAME>","thread_id":"qa-crisis","message":"hi"}' | head -c 400

# 4. Revive (use the agent_id from step 2)
curl -sS -X POST "http://localhost:8904/kid-agent/<AGENT_ID>/revive" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# 5. Confirm chat works again
curl -sS -N -X POST http://localhost:8904/kid-chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"user_id":"<USER_ID>","kid_name":"<KID_NAME>","thread_id":"qa-crisis","message":"hi"}' | head -c 400
```

**Expected.**
- Step 1: SSE stream emits `'I'm really glad you told me...'` chunks, then a `crisis` event, then `[DONE]`.
- Step 2: `locks` array contains the kid's agent with `category` and `severity: crisis`.
- Step 3: SSE emits the freeze message (`'Your grown-up needs to check in with you...'`) and `[DONE]` — no LLM call.
- Step 4: `{ok: true, agent_id, kid_name}`.
- Step 5: Normal LLM-driven streaming response.

**Watch for:** if step 3 returns the original crisis script instead of the freeze message, the persistent lock isn't being read. If step 5 is still gated, the `set_kid_agent_enabled(True)` didn't run.

**Important caveat:** parent push notification (APNs) is **NOT** wired yet. Crisis events still write to `moderation_events` and fire a Slack alert (if `SLACK_WEBHOOK_URL` is set), but the parent device gets no notification. Don't put a real kid in front of this until APNs lands — see roadmap.

## 7. Cascade `DELETE /family/{user_id}` *(backend)*

**What changed.** New parent-token-only endpoint that wipes a family across 9 tables (transcripts, agents, credentials, moderation events, crisis locks, auth tokens, summaries, consent records, user_data) and writes an `audit_events` row.

**Test path.**
```
# 1. Issue a token for a victim user_id
TOKEN=$(curl -sS -X POST http://localhost:8904/auth/issue-token \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"qa-deleteme"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["token"])')

# 2. (Optional) Seed a profile so there's something to delete
curl -sS -X POST http://localhost:8904/profile/seed \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"qa-deleteme","parent_name":"QA","kids":[{"name":"Ari","age":"7","temperament":"sensitive"}]}' \
  -o /dev/null -w "seed: %{http_code}\n"

# 3. Cascade delete
curl -sS -X DELETE "http://localhost:8904/family/qa-deleteme" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool

# 4. Confirm the token is now invalid (token row was deleted)
curl -sS -o /dev/null -w "after delete: %{http_code}\n" \
  http://localhost:8904/memory/qa-deleteme -H "Authorization: Bearer $TOKEN"

# 5. (Optional) Verify the audit row landed
duckdb mvp-backend/data/mvp.duckdb \
  "SELECT action, user_id, actor, details FROM audit_events ORDER BY created_at DESC LIMIT 1;"
```

**Expected.**
- Step 3: response includes per-table delete counts: `auth_tokens: 1`, `user_data: 1` (if you seeded), others 0.
- Step 4: `401` — the token is gone.
- Step 5: one row, `action = 'family_deleted'`, `user_id = 'qa-deleteme'`, `details` JSON containing the same counts.

**Cross-tenancy guard:** the endpoint uses `Depends(current_user)` + `authorize_user_match`. Try deleting someone else's data and confirm `403`:
```
curl -sS -X DELETE "http://localhost:8904/family/some-other-user" \
  -H "Authorization: Bearer $TOKEN" -o /dev/null -w "wrong-user: %{http_code}\n"
```
Expected: `403`.

## 8. Voice hardening *(iOS only)*

**What changed.**
- STT now requires on-device recognition (`requiresOnDeviceRecognition = true`) AND checks `recognizer.supportsOnDeviceRecognition` before starting. If the device or locale doesn't support it, the controller refuses with a user-visible error rather than silently routing audio to Apple servers.
- TTS playback now stops STT first — prevents the agent's own voice from being picked up as kid input (self-amplifying loop).
- 3-second silence timeout auto-stops listening (kids start sentences and don't always finish).
- Audio session uses `defaultToSpeaker`.

**Test path (iOS Simulator — note the simulator's STT is limited; a real device gives better signal):**
1. In the kid-agent flow, tap into voice mode.
2. **On-device gate:** if you're on a device/locale where on-device STT isn't supported, you should see the message *"On-device speech recognition isn't available on this device or language. Tap to use text instead."*
3. **Self-loop defense:** trigger a TTS reply, then quickly tap the mic before TTS finishes. Expected: nothing happens (you'll see *"Wait for me to finish talking before you start."*) until TTS completes.
4. **Silence timeout:** start listening, say one word, then go silent. After ~3 seconds, listening should auto-stop (mic icon turns off). Confirm `transcribedText` reflects what you said (not a partial).
5. **Loop test:** start listening, say something the agent will respond to, watch TTS play out — listening should NOT have re-engaged during TTS.

**Watch for:** if the simulator falls back to network STT (some locales do), step 1 should refuse instead of silently working.

## 9. `entrypoint.sh` no longer wipes the DuckDB *(backend / Railway)*

**What changed.** The `rm -f /app/data/*.duckdb*` on container start was destroying `kid_messages`, `moderation_events`, `consent_records`, and `auth_tokens` on every Railway push (those tables aren't in the parquet seed export). Removed. The volume now retains state across deploys; only stale `.duckdb.wal` files are cleared.

**Test path** (only meaningful against Railway deploy; on local you skip this).
1. Deploy the new image: `cd mvp-backend && railway up --detach`.
2. After the deploy succeeds, hit the production health URL and the moderation-events endpoint (or a parent-token-protected endpoint that returns historical data) and confirm previous rows are still there.

**Expected.** Audit history, consent records, and active tokens survive. If something looks suspiciously empty, ssh in (`railway run bash`) and `ls /app/data/*.duckdb` — the file should be present and recent.

## What's NOT in this release (still on the roadmap)

These were called out by the critic review and intentionally deferred. Don't QA them — they're not implemented.

- **APNs parent push** for crisis events. Lock-and-freeze works, but the parent doesn't get a notification on their phone yet.
- **App Attest / Apple Sign-In** on `/auth/issue-token`. Closed beta is one leaked `user_id` away from full read on a victim family.
- **`/metrics`** endpoint and golden-signal histograms.
- **Cost ledger** — no per-family OpenAI dollar cap.
- **CI** running unit tests + eval suite.
- **12-month retention enforcement** — old transcripts aren't auto-purged.
- **Persistent LangGraph checkpointer** — kid chat continuity is lost on every server restart.
- **Architecture cleanup** — `server.py` transaction-script extraction, `KidAgent` domain object, `invariants → Letter` rename, etc.

Full list lives in `docs/code-review-findings.md` and the new "Family Companion v0 — pre-beta blockers" section of `docs/roadmap.md`.
