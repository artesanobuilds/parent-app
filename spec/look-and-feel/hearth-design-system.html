Hearth — Design System for parent-app.

Cream canvas, ink text, olive accent, photo tiles. A steady hand on the shoulder of an overwhelmed parent — editorial weight, quiet chrome, real photography, sober where it counts. Architecture borrowed from SonderMind's Iris 2.0; the brand language is ours.

version: 1.0.0 status: ✅ active owner: Miguel last_updated: 2026-05-31

section 01

HEARTH principles.

Every Hearth output must satisfy all six. If a generation satisfies five, it is not Hearth.

H

Held

A steady hand on the shoulder of a tired parent. Visual weight reduces stress, never adds to it. Generous whitespace, one clear next action, no decorative motion that demands attention.

E

Editorial

Content first; chrome quiet; photography earns its space. Fraunces carries headlines, Inter carries reading and UI, JetBrains Mono is metadata only. Magazine spreads, not UI widgets.

A

Adaptive

44pt touch min, respects reduced-motion, designed to invert cleanly in dark mode (Phase 2). WCAG 2.1 AA on every shipped token pair. Cognitive accessibility is non-negotiable.

R

Real

No stock illustrations, no chirpy mascots, no "Sarah, mom of two!" Photography looks like the actual parents who use the app — varied bodies, ages, skin tones, photographed in their actual rooms.

T

Trustworthy

Kid-agent, crisis-lock, and safety surfaces use sober variants. No playful animations, no saturated photo tiles, no decorative serif in chrome. When a parent is scared, the app gets quieter.

H

Hearth

Gathering place: warmth without saccharin. Cream not white, olive not mint, ink not pure black on most surfaces. The name is the brief — a hearth is warm, central, communal, slow.

section 04

Components — live gallery.

Each block renders the component in real HTML next to its spec drawer. Tokens used are echoed at the foot of each card.

Buttons · 3 variants × 3 sizes

primary · one per screen
secondary · adjacent counter-verb
quiet · inline / nested
danger = modifier on secondary · disabled state
spec ▸ buttons.md
  • One primary per screen, full stop. If you need two, one is secondary.
  • danger is a modifier on secondary, not a variant — destructive actions stay quiet until invoked.
  • Sizes sm (32h · type/label), md (40h · type/title-md), lg (48h · type/title-md). iOS hit target is 44pt minimum regardless of visual height — pad the tap area, not the chrome.
  • shape/pill permitted on lg primary/secondary in CMS landing only. Forbidden in iOS in-app chrome.
  • primary CTAs on warm photo tiles (saffron, rose) are forbidden — the on-photo-light label fails AA against olive-on-warm.
  • On sober surfaces only secondary and quiet are permitted — never primary saturated fill.
  • Reduce-motion replaces press-scale with fill darken 4%; no scale, no spring.

Forms · field states

we'll send your weekly digest here.
helps us match articles to your kid's stage.
this email looks off — try again?
complete the previous step first.
spec ▸ forms.md
  • Labels live ABOVE the input. Never inside. Never floating.
  • One field per row on iOS; CMS may pair two short fields at ≥md viewport.
  • Helper text and error text occupy the same vertical slot — never both.
  • Errors are warm and specific: "we need a valid email to send your weekly digest" — not "invalid format".
  • Required fields are marked with a trailing · in accent/default, never an asterisk.
  • Sizes: sm 36h, md 44h (default — meets touch min), lg 52h.
  • On sober surfaces no inline validation animations — validate on blur only.

spec ▸ cards.md
  • Four variants: article (4:5 hero, byline) · category (saturated photo tile) · post (parent post, formerly community) · sober (kid-agent / safety, formerly kid-agent).
  • Photo on article + category is non-negotiable. No photo = use the post variant instead.
  • Category tiles use one photo token per tile; never gradient between two photo/* colors.
  • A library grid shows at most 3 distinct photo/* tokens above the fold (Rose LA discipline).
  • Sober cards forbid: photo, saturated fill, decorative serif, hover affordance, skeleton loading.
  • Cards lift via border/hairline + bg/elevated on canvas — not shadow. elevation/1 is reserved.
  • Cards never nest. If you want a card-in-card, you want a sheet.

Chips · tag, filter, category

5 min · audiobook advice tweens tag · read-only metadata
filter · toggleable
category · navigates
spec ▸ chip.md
  • Minimum height is 28. Below that, you have a label, not a chip.
  • Tag chips are read-only — they do not navigate or toggle.
  • Filter pills toggle; active filters fill ink/primary (high contrast), not accent/default.
  • Counts appear inline with a middle-dot separator: "audiobooks · 12". Never parentheses.
  • On photo tiles, chips switch fill to bg/elevated @ 90% with ink/primary — never transparent with on-photo ink.
  • Filter "clear" affordance has a 44pt minimum hit area regardless of its 28-32pt visual height.

States · empty · loading · error

▢
nothing saved yet.

tap the bookmark on any article to start a library.

!
couldn't load posts.

your connection looks shaky. saved articles still work.

loading…
spec ▸ empty.md
  • Empty states get a warm icon, never a sad face, never an exclamation mark.
  • Loading copy ("loading…") only appears after 1500ms — don't flash it for fast requests.
  • Skeleton blocks match the real layout's grid; never use generic "lorem" boxes.
  • Skeletons are FORBIDDEN on kid-agent and crisis surfaces — use spinner only. They imply content will arrive, which is a trust violation on safety paths.
  • Retry actions are secondary, never primary — the parent didn't fail, the request did.
  • First-run surfaces always include a photo or photo-tile hero — never icon-only.

Nav · iOS tab bar (5 slots)

spec ▸ nav.md
  • Five tab slots, period. Adding a sixth requires removing one.
  • Center "ask" is always slot 3, always raised, always shape/pill in accent/default.
  • Badge is a dot, never a number. If urgency requires a count, escalate to a sheet.
  • Tab labels are always visible — never icon-only.
  • Top-nav title is centered on iOS, left-aligned on CMS — do not mix.
  • Sub-nav chips scroll horizontally on iOS — never wrap. Wrap on CMS only.

section 05

Surfaces — iOS & CMS.

Same tokens. Different density, different hit-targets, different motion budgets. The brand DNA survives the trip from iPhone to 15" laptop.

primary target

iOS · SwiftUI

Tokens land in Theme.swift + Theme+Typography.swift. No raw hex, point value, or font name lives in a View file — CI fails on token violations.

Touch floor: 44pt × 44pt for every tappable region. Adjacent 44pt regions never touch (gap ≥ .hearth300).

// Token → SwiftUI accessor
Color.hearthCanvas          // bg/canvas
Color.hearthInkPrimary      // ink/primary
Color.hearthAccent          // accent/default
.padding(.hearth700)        // 24pt page gutter
.cornerRadius(.hearthRadiusLg) // shape/lg · 20pt
.font(.hearthDisplayLG)     // Fraunces 40/44 · 600

// Reduce motion routes through a single resolver
.animation(Animation.hearthSpring, value: isPressed)

Light-mode locked for Phase 1 — dark-mode tokens land in Phase 2.

secondary target

CMS · React + Tailwind

Tokens land in tailwind.config.ts + tokens.css. No bg-[#...], no p-[13px], no arbitrary Tailwind values — ESLint rule fails the build.

Denser than iOS: page gutter 16px, card pad 16px, button md 36h. No 44pt floor on desktop. Body type stays at 15px.

{/* Token → Tailwind class */}
<div className="bg-canvas text-ink-primary p-700">
  <h1 className="font-display text-display-lg">
    library
  </h1>
  <button className="bg-accent text-ink-on-photo-light
                     rounded-md px-500 h-9">
    publish
  </button>
</div>

/* fonts self-hosted; never the Google CDN at runtime */

Springs are forbidden on CMS — mouse cursors hate them. Use motion/fast easeOut.

section 06

Photography — Mode A & Mode B.

Photography is the dominant visual layer. Two modes by lifecycle: Midjourney now, hired photographers later. Universal rules (casting, lighting, composition, palette) apply to both.

v1 — active

Mode A — Midjourney.

Production photography source for v1. MJ can hit our exact palette and contrast targets when prompted with locked hex values + --style raw. Two simultaneous techniques in every prompt: (a) cite hex inline, (b) --style raw --v 6 (upgrade to v7 when available).

Every generation passes two QA gates — palette compliance (ΔE ≤ 6 from target hex) and the uncanny test (real family, real room, no plastic-skin sheen).

post-launch — reference

Mode B — Human photographers.

The day we shift from generated to shot photography. 6-8 families per shoot day, varied across ages, body types, skin tones, household structures. Not model agencies — independent casting via parenting communities. Audition signal that matters: can they ignore the camera.

Real homes, never studios. North-facing window, side light. A Hearth LUT clamps subject tones between ink-700 and ink-500, photo-tile backgrounds within ΔE ≤ 5 of the assigned hex.

photo tiles · 4 only (saffron, rose, royal, forest). clay + sand retired from v1.

Crisis surface rule. No photography on any crisis-lock or near-crisis surface. Type-only — type IS the design. bg/sober canvas, ink/primary text, no decorative elements. A photograph in a crisis context is a tonal violation regardless of how well it's shot.

section 07

Voice — good copy, bad copy.

Warm, concrete, second-person, present-tense. Functional in chrome, editorial in long-form, sober in crisis. The pattern in every good error: what happened (specific) — what you can do next (specific) — no shame, no exclamation, no emoji.

good · article fetch failed
couldn't load articles. pull down to retry.
specific · actionable · no shame · no `!`
bad · tech-speak, no next step
Error 500: Internal Server Error
unrecoverable · alarming · blames the system
good · login wrong password
that password doesn't match. try again, or reset it below.
no blame · second-person · path forward
bad · blames the parent
Invalid input! Please try again.
accusatory · `!` · vague
good · network offline
you're offline. saved articles still work; the rest is waiting on a connection.
acknowledges state · names what still works
bad · cute when it shouldn't be
oops! something went sideways 😅 our gremlins are on it!
emoji in chrome · brand `we` · no info
good · photo upload too large
photo is over 10mb. try a smaller one or take a new shot.
names the limit · two paths forward
bad · brand `we` + corporate
We're sorry, but we are unable to process your request at this time.
marketing voice · no specifics · hedge
good · form field missing
your kid's age helps us pick the right articles. add it to keep going.
explains the why · names the unblock
bad · vague + alarming
Something went wrong. Please contact support.
no signal · no next step · escalation off-app

crisis-surface tone

this conversation is paused.

a real person can help right now: 988 (call or text). it's free and open 24/7.

sober · declarative · no metaphor · no `!` · no emoji · no photography

section 08

Logo — three directions.

Three wordmark explorations for the parent-app. One ships. The other two die honorable deaths. The wordmark is hand-drafted from Fraunces in Glyphs / Illustrator — MJ output is reference only.

MVP
direction A · default recommendation

Wordmark only.

All-caps Fraunces ExtraBold, tight tracking. Reads as confident, editorial, grown-up — Wonder Valley energy. Scales cleanly from 24pt nav to 1024px launch. Risk: no mark, so the App Store icon is a single-letter crop.

MVP
direction B · only if we fund a real mark

Wordmark + mark.

Wordmark plus a small geometric flame-or-doorway glyph at cap height. Gives us a brand mark that survives at 16×16 and 1024×1024. Risk: wellness-cliché territory unless drafted by an actual designer — flames are a crowded field.

mvp.
direction C · if tonal calibration says warmer

Lowercase + dot.

Lowercase Fraunces Regular, period in accent/default olive. Friendly bookshop sign. Warmest of the three; most approachable on first-time splash. Risk: less authoritative on health-adjacent surfaces. Monochrome fallback drops the dot.

AI loading rules.

Operating manual for AI agents using Hearth. Two files load every session, unconditionally. Component and surface specs load by intent — pull only what the task touches.

  • voice.md — when writing copy / error strings / headlines

  • midjourney-prompts.md — when generating production photography
generation rules — hard branches
  • 1. never emit a hex outside DESIGN.tokens.md — all colors resolve to a semantic token
  • 2. never invent a token — token names are an allowlist
  • 3. ask before generating if the surface is ambiguous (iOS / CMS / brand)
  • 4. reference, don't copy — emit token names, never paste hex
  • 5. one CTA per screen — if two primary buttons, demote one to secondary
  • 6. reduced-motion is a hard branch — every motion uses motion/instant collapse
  • 7. sober variant for kid-agent / crisis-lock / safety surfaces
  • 8. no raw Color(hex:) / bg-[#...] / inline styles — linted out
  • 9. cite the tokens used — every component spec ends with a `Tokens used` block
  • 10. when in doubt, reduce — Hearth fails by addition more often than subtraction
